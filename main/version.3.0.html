tomato-v3.0

Section author: Peter Kraus

Developed at the ConCat lab at TU Berlin.

Warning

Minimum python version has been increased to python>=3.11 in tomato-3.0.

Changes from tomato-2.2 include:

  • The state of drivers, components, and pipelines is now stored in a sqlite3 database for persistent storage.

  • The configuration files (settings file, devices file) are now parsed by the daemon into a new tomato.models.DeviceFile model. This model holds the Component, Device, and Driver models that are required to build the Pipeline models.

    Note

    As a consequence of this change, the tomato and passata API has changed.

  • Included a new driverinterface_3_0 module. The key changes here are:

    • The abstract class representing the registered components is now called ModelComponent. The name "Component" (or cmp) should now be used consistently throughout instead of "Device".

    • The ModelInterface.ComponentFactory() is no longer an abstract function. By default it attempts to instantiate the Component class in the top level of the driver module. As a consequence, the ModelInterface has no abstract methods/functions.

    • The tomato.models.Component model now automatically generates its Component.name. As a consequence, the ModelInterface.devmap has the name as a key and the correct name is returned appropriately throughout the code.

    • Reworked ModelComponent.status(), which is now an abstract function, that should now return Status objects.

    • Reworked ModelComponent.stop(), reset(), and quit():

      • stop() is a helper function that should stop any activity on the component and bring it component into a safe state. It is called as part of ModelInterface.cmp_stop(), cmp_reset(), and cmp_quit().

      • reset() is a helper function that should bring the component into a state ready for new Tasks. It is called after stop() in ModelInterface.cmp_reset(), at the completion of every Payload.

      • quit() is an abstract helper function that should ensure the component can be released by tomato. It is called after stop() in ModelInterface.cmp_quit(), which is called whenever the driver process exits via an atexit handler.
